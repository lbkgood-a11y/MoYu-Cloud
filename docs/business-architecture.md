# MoYu-Cloud 业务架构

## 定位

MoYu-Cloud 是独立开发者的创作神器：帮助一个人把产品想法快速变成可运行、可修改、可独立部署的真实产品。

核心链路不是“管理后台”，而是：

```text
想法 → 项目 → 业务模型 → 生成模块 → 运行验证 → 独立部署 → 持续创作
```

## 业务域分层

### 1. 创作工作台（核心域）

面向创作者的主入口，负责管理产品想法、项目和当前创作进度。

- 项目创建向导
- 项目名称、描述和技术模板
- 创作阶段：想法、建模、生成、验证、发布
- 最近项目和快速继续

现有映射：`ProjectWizardController`、`ProjectWizardRequest`。

### 2. 模型设计器（核心域）

把产品想法拆解为可执行的业务模型。

- 数据表、字段和基础关系
- 字段类型、必填、默认值和唯一性
- 列表、表单、查询元数据
- 业务状态和基础校验

现有映射：`modeling`、`DataTableEntity`、`DataFieldEntity`、`ModelingView`。

### 3. 模块生成器（核心域）

把模型转换为实际项目代码。

- 数据库迁移
- Java 后端模块
- Vue 页面和 API
- 权限标识
- 基础测试和项目文档
- 生成文件预览与导出

现有映射：`CrudCodeGeneratorService`、`GeneratedModule`、`GeneratedFile`、`CodeExportController`。

### 4. 产品运行底座（支撑域）

为生成的个人产品提供可直接使用的基础能力，不作为 MoYu-Cloud 的主要卖点。

- 登录与会话
- 用户、角色、菜单
- 部门和字典
- 按钮、字段和数据权限
- 统一异常、分页和响应

现有映射：`auth`、`system`、`shared`、`frontend/views/system`。

### 5. 创作质量保障（支撑域）

确保生成结果可以运行和继续修改。

- 权限和字段脱敏
- 操作日志
- API 与数据库一致性检查
- 构建、测试和启动检查
- 生成失败的明确反馈

现有映射：`RoleFieldPermissionService`、`DataMaskingService`、`audit`、相关测试。

### 6. 发布与资产（支撑域）

帮助创作者把成果带出工具并沉淀复用。

- Docker 和本地部署
- 环境变量模板
- 项目 README
- 模板、模块和字段片段复用
- 导出到 Git

现有映射：`deploy`、项目文档和代码导出能力。

## 现有功能重新归位

| 当前功能 | 新架构角色 | 产品表达 |
| --- | --- | --- |
| 登录、用户、角色、菜单 | 产品运行底座 | 生成项目自带的基础能力 |
| 部门、字典 | 产品运行底座 | 减少产品初始化工作 |
| 客户 CRUD | 第一个创作样板 | 证明从模型到产品的闭环 |
| 数据表建模 | 模型设计器 | 描述产品业务对象 |
| 字段权限和脱敏 | 创作质量保障 | 默认生成安全规则 |
| 操作日志 | 创作质量保障 | 让产品具备可追溯性 |
| 代码导出 | 模块生成器 | 代码归创作者所有 |
| Docker 部署 | 发布与资产 | 一键把作品带到生产环境 |

## MVP 主流程

1. 创作者创建一个项目。
2. 选择模板并填写产品描述。
3. 定义客户等业务对象和字段。
4. 配置列表、表单和基础权限。
5. 生成后端、前端、迁移和测试代码。
6. 在工作台预览并导出代码。
7. 本地运行或 Docker 部署生成项目。
8. 回到模型继续添加下一个业务对象。

## 暂缓能力

暂不把以下内容纳入业务主架构：多租户 SaaS、流程设计器、微服务治理、插件市场、在线云端托管和企业级规则中心。

## 判断标准

每增加一个功能，都必须回答：

> 它是否让独立开发者更快把想法变成可用产品，或让已经做过的能力在下一个项目中更容易复用？

如果不能，应暂缓。
