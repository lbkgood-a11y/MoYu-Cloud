# MoYu-Cloud 构建计划

## 总体策略

先做完整闭环，再逐步扩展能力。每个阶段都必须产出可运行、可验证、可交付的结果，避免“大而全”导致迟迟无法落地。

## 阶段一：MVP 闭环

目标：30 分钟内创建并部署一个基础业务系统。

范围：

- 项目创建向导和单体后台模板
- 登录、用户、角色、菜单、组织管理
- 基础按钮权限和数据权限
- 数据表建模与 CRUD 自动生成
- 字典、文件、操作日志
- 本地一键启动与 Docker 一键部署
- 代码导出、Git 管理和基础项目文档

验收标准：

- 新用户无需人工介入即可完成项目创建和启动
- 一个简单业务表可以自动生成增删改查页面和接口
- 权限、日志和异常处理默认可用
- 生成结果可以独立运行，不依赖平台在线服务

## 阶段二：效率增强

目标：覆盖更多高频业务场景，减少手工修改。

- 表单布局、校验、查询和导入导出配置
- 页面模板和可复用业务组件
- 代码生成差异预览和增量更新
- API 文档自动生成
- 配置中心、定时任务和消息通知
- 多环境配置和数据库迁移

## 阶段三：流程与交付

目标：让复杂业务流程和上线运维同样简单。

- 审批流程设计器
- 会签、或签、转办、加签和条件分支
- 状态机与业务规则
- CI/CD 集成、健康检查和版本回滚
- 日志检索、指标监控和错误追踪

## 阶段四：平台生态

目标：把团队经验沉淀为可共享资产。

- 插件和模块扩展机制
- 行业模板和解决方案
- 组件、页面和流程市场
- 团队级模板管理与权限控制
- 社区贡献、版本治理和兼容性规范

## 关键衡量指标

| 指标 | MVP 目标 |
| --- | --- |
| 首个可运行项目创建时间 | ≤ 30 分钟 |
| 标准 CRUD 模块交付时间 | ≤ 15 分钟 |
| 基础项目手工配置步骤 | ≤ 5 步 |
| 生成项目独立运行能力 | 100% |
| 关键流程文档覆盖率 | 100% |

## 每个版本的完成定义

- 功能有清晰的使用入口和默认配置
- 有最小可运行示例
- 有自动化测试或可重复验证步骤
- 有升级、回滚和异常处理说明
- 不依赖开发者记忆隐含操作

## 近期优先级

1. 先建立可运行的项目骨架和统一规范。
2. 再完成权限、用户、日志等通用能力。
3. 接着打通数据建模到 CRUD 生成的闭环。
4. 最后扩展流程、运维和生态能力。
