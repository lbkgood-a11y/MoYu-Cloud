# MoYu-Cloud MVP 基础工程方案

## 当前阶段

当前目标是先完成一个可运行的“客户管理系统”样板，验证从项目启动到业务交付的最小闭环。

## MVP 范围

### 必须具备

- 用户登录
- 用户、角色、菜单管理
- 基础按钮权限
- 客户信息增删改查
- 分页、关键词查询和表单校验
- 操作日志
- 本地启动说明
- Docker 部署说明

### 暂不纳入

- 可视化流程设计器
- 插件市场
- 多租户 SaaS
- 复杂数据权限
- 在线云端项目托管

## 推荐工程结构

```text
MoYu-Cloud/
├─ backend/          # 服务端应用
├─ frontend/         # 管理端应用
├─ deploy/           # Docker、环境和数据库脚本
├─ examples/         # 可运行示例和演示数据
├─ scripts/          # 初始化、检查和生成脚本
├─ docs/             # 产品、开发和部署文档
└─ README.md
```

## 模块边界

### 基础模块

- `auth`：登录、会话和密码校验
- `system`：用户、角色、菜单和权限
- `audit`：操作日志和登录日志
- `common`：统一响应、异常、分页和基础工具

### 示例业务模块

- `customer`：客户信息、联系人、状态和备注

示例业务模块必须依赖基础模块提供的能力，但不能把基础模块实现复制到业务代码中。

## 第一个验收场景

1. 按 README 完成环境准备并启动服务。
2. 使用默认管理员登录。
3. 创建一个“销售人员”角色。
4. 为角色授予客户列表和编辑权限。
5. 新建、查询、修改和删除一条客户记录。
6. 在操作日志中看到对应的变更记录。
7. 使用 Docker 启动一套独立实例。

## 完成定义

- 新开发者可以在 30 分钟内启动示例。
- 核心接口和页面有最小自动化验证或可重复检查步骤。
- 默认配置可以直接运行，敏感配置通过环境变量提供。
- 业务代码与基础能力代码边界清晰。
- 后续代码生成器可以复用客户模块的目录和命名约定。

## 下一项实施任务

建立 `backend/`、`frontend/`、`deploy/`、`examples/` 和 `scripts/` 工程目录，并先完成基础 README 与环境配置模板；随后实现登录和系统权限模块。
